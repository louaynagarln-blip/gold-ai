# تقرير التأهيل — AI GOLD TRADER 0.3-safety

## الحكم

**التطبيق غير مكتمل كتطبيق تداول تلقائي. التنفيذ عند الوسيط غير مطبق ومقفل.**
المكتمل: بناء محرك منفصل للتحليل والمخاطر مع محاكاة بيانات MT5، وواجهة Android للتحكم والقراءة، واختبارات آلية محلية. لا يوجد خادم MT5 متصل بهذه الجلسة ولا جهاز المستخدم متصل.

## نتائج محلية حقيقية

- 45 اختبار Python ناجحاً: المؤشرات، تأكيد الاتجاه، صلاحية الإعدادات، رفض NaN، حساب اللوت وتكاليفه، رفض مخاطرة الحد الأدنى، تحقق هوية الحساب، رفض حساب حقيقي وتبدل الحساب، رفض سعر قديم وانقطاع الطرفية وحالة أوامر وتاريخ صفقات مجهولة، حد الخسارة، الإيقاف وانتهاء النبض، منع تكرار المرشح بنفس الشمعة، حماية endpoints ومصادقة الخدمة.
- هذه الاختبارات تستعمل MT5 وهمياً في الذاكرة؛ لا تثبت تنفيذ أوامر ولا اتصال FxPro.
- 2000 دورة قياس CPU على بيانات مصطنعة: الوسيط 0.784361 ms، P95 يساوي 1.124233 ms، والأقصى 2.856420 ms في بيئة هذه الجلسة. القياس يتضمن إنشاء شموع الاختبار والتحليل والتحقق منها.
- زمن وصول سعر FxPro: غير مقاس. زمن تأكيد أمر: غير مقاس. تجربة تشغيل طويلة Demo: لم تُجرَ.
- الاختبار الأول فشل بسبب طريقة تشغيل discovery من مجلد أعلى؛ أُعيد من جذر المشروع. اختبار آخر فشل لأن نص التوقع لا يطابق رسالة الرفض، وصُحّح التوقع؛ ثم اجتازت المجموعة 45/45.

## أخطاء البناء المكتشفة والمعالجة

1. android-actions/setup-android كان يطلب حزمة SDK محذوفة `tools`. استُبدل باستدعاء sdkmanager لحزم platform 35 وbuild-tools 35 وplatform-tools.
2. Java يستهدف JVM1.8 وKotlin يستهدف JVM17. ضُبط الاثنان على 17.
3. رفع diagnostics كان يتطلب نجاح البناء. أصبح تقرير الأخطاء يُرفع عند النجاح والفشل.
4. workflow كان يكتب نتيجة البناء إلى main ويولد تعديلات آلية غير لازمة. أزيلت كتابة التقرير التلقائية للمستودع.
5. أسعار موقع الويب القديمة كانت مولّدة عشوائياً. أزيلت وأصبحت الواجهة تعرض غياب التغذية الفعلية، مع إبطال الكاش القديم.

6. تعارض اسم layout داخل عناصر Android في Kotlin؛ استُخدم مرجع MainActivity الصريح للوصول إلى الحاوية.

7. مكتبات إطار Android test القديمة لم تكن في مسار الترجمة؛ أضيفت للمترجم كاعتماد اختياري، ولبيان تطبيق الاختبار.

## المخاطر التقنية المتبقية

يلزم Windows VPS أو جهاز دائم يشغل MT5. البيئة السحابية الحالية Linux لا تحتوي MT5 أو SDK Android محلياً؛ يجري البناء والمحاكي في GitHub Actions.
الاعتماد على كلمة FxPro في شركة الحساب جزء من فحص الهوية وليس إثبات أصالة مستقلاً؛ الثقة تعتمد على طرفية أصلية وخادم HTTPS موثوق ورقم وخادم حساب متوقعين. يجب اختبار ذلك مع الحساب الفعلي.
المواصفات والعمولة والرمز الدقيق للذهب قد تختلف بحسب الحساب. الافتراضات غير المؤكدة تحظر خطة الدخول.
حد الخسارة المستخدم UTC وإجمالي خسائر وليس P/L صافياً. تعطل تطبيق الهاتف يمنع استئناف المحاكاة، ويوقف الخادم بعد انتهاء مهلة النبض؛ STOP عن بعد يحتاج وصول الشبكة.
واجهة Android تقيس الاتصال وتعرض زمن التحليل وعمر السعر، لكنها ليست محرك سكالبينغ. كلمة سرعة لا تعني أن زمن الوسيط قيس.
لا تُحفظ كلمة مرور FxPro، ولا يُطلب إرسالها في الدردشة. رمز الربط لا يحفظ على هاتف Android.

## الخطوة التالية اللازمة

توفير طرفية MT5 على خادم Windows دائم وإتاحة وصول إداري مناسب لإعداد الربط، ثم ربط Demo والتحقق من الحساب ومواصفات الذهب وHTTPS واختبار الهاتف. لا يحتاج المستخدم كتابة كود.
بعد ذلك تُبنى وتُؤهل طبقة التنفيذ بتسوية حالة الأوامر وإعادة الاتصال. إرسال أول أمر Demo يحتاج موافقة صريحة منفصلة بعد نجاح الاختبارات. لا توجد حالياً موافقة أو أهلية للإرسال.
